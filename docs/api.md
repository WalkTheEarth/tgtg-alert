# HTTP API

The REST API the phone app uses. Documented so you can script against it, build
your own client, or wire it into Home Assistant.

Default base URL: `http://<host>:8787`.

---

## Authentication

Every endpoint except `/health` requires a bearer token:

```
Authorization: Bearer <TGTG_API_TOKEN>
```

The token is generated by `tgtg-alert init`, lives in `.env`, and is embedded in
the pairing QR. Compare with `tgtg-alert pair` if you have lost it.

Failures return `401` with `{"detail": "invalid or missing API token"}`.

> `/health` is deliberately unauthenticated so container healthchecks work
> without the token. It returns only `{"ok": true, "version": "..."}`.

**There is no `/api` prefix on `/health`** — note the difference.

---

## Conventions

- All bodies are JSON. Send `Content-Type: application/json`.
- Money is in **major units** (`4.50`), not the minor units the TGTG API uses.
  Conversion happens at the boundary so clients never deal with cents.
- Timestamps are naive UTC strings from SQLite: `2026-10-13 17:04:09`. Append
  `Z` before parsing in JavaScript, or you will be hours out.
- Errors are `{"detail": "message"}` — FastAPI's default shape.

### Status codes

| Code | Meaning |
|---|---|
| `200` | OK |
| `201` | Created |
| `204` | Deleted. No body. |
| `400` | Bad request — nothing to update, malformed body. |
| `401` | Bad or missing token. |
| `404` | No such watch or device. |
| `409` | Conflict — not logged in to TGTG, or no devices to push to. |
| `422` | Validation failure. Coordinates out of range, radius too large. |
| `429` | Too Good To Go is rate limiting or blocking the server. |

## `GET /api/status`

Everything the app's Settings screen shows. **The first thing to check when
something seems wrong.**

```bash
curl -s -H "Authorization: Bearer $TOKEN" localhost:8787/api/status | jq
```

```json
{
  "version": "0.1.0",
  "account": "you@example.com",
  "logged_in": true,
  "poll_interval_seconds": 600,
  "watches": 3,
  "devices": 1,
  "last_run": {
    "at": "2026-10-13 17:04:09",
    "items_seen": 62,
    "matched": 5,
    "alerts": 1,
    "errors": 0,
    "blocked": false,
    "note": null
  },
  "blocked_in_last_24h": 0
}
```

| Field | Notes |
|---|---|
| `logged_in` | `false` means the server has no TGTG session. Run `login`. |
| `last_run` | `null` until the first pass completes. |
| `last_run.blocked` | The most recent pass was refused by DataDome. |
| `blocked_in_last_24h` | **The one to watch.** Non-zero means alerts have been silently paused. |

## Watches

### `GET /api/watches`

```bash
curl -s -H "Authorization: Bearer $TOKEN" localhost:8787/api/watches | jq
```

```json
[
  {
    "id": 1,
    "label": "Coffee near work",
    "store_pattern": "Blank Street",
    "bag_pattern": null,
    "max_price": 5.0,
    "latitude": 51.5072,
    "longitude": -0.1276,
    "radius_km": 5,
    "enabled": true,
    "notify_on_increase": false,
    "baselined": true,
    "created_at": "2026-10-13 16:04:09",
    "tracked_items": 14,
    "items_in_stock": 2
  }
]
```

`baselined: false` means the watch has not completed its first poll and will not
alert yet. `tracked_items` and `items_in_stock` are what the CLI's `watch list`
renders.

### `POST /api/watches`

```bash
curl -s -X POST localhost:8787/api/watches \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{
        "label": "Coffee near work",
        "store_pattern": "Blank Street",
        "max_price": 5,
        "latitude": 51.5072,
        "longitude": -0.1276,
        "radius_km": 5
      }'
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `latitude` | float | **yes** | −90 to 90 |
| `longitude` | float | **yes** | −180 to 180 |
| `label` | string | no | Display name. |
| `store_pattern` | string \| null | no | Case-insensitive substring. |
| `bag_pattern` | string \| null | no | Case-insensitive substring. |
| `max_price` | float \| null | no | 0–1000, major units. |
| `radius_km` | int | no | 1–100, default 10. |
| `notify_on_increase` | bool | no | Default `false`. Noisy. |
| `enabled` | bool | no | Default `true`. |

Returns `201` with the created watch. Omitting every pattern creates the "any bag
nearby" rule.

### `PATCH /api/watches/{id}`

Partial update. Send only what changes.

```bash
curl -s -X PATCH localhost:8787/api/watches/1 \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"enabled": false}'
```

Accepts `label`, `store_pattern`, `bag_pattern`, `max_price`, `radius_km`,
`notify_on_increase`, `enabled`. **Coordinates are not updatable** — delete and
recreate to move a watch.

An empty body returns `400`.

### `DELETE /api/watches/{id}`

Returns `204`. Also deletes that watch's stored observations. Alert history is
kept.

### `POST /api/watches/{id}/rebaseline`

```bash
curl -s -X POST localhost:8787/api/watches/1/rebaseline \
  -H "Authorization: Bearer $TOKEN"
```

Forgets the current stock picture and clears stored observations. The next poll
re-surveys silently instead of alerting on everything as if it were new.

**Use after downtime.** If the server was off for a week, everything it sees on
restart looks new.

## Devices

### `GET /api/devices`

```json
[
  {
    "id": 1,
    "platform": "ios",
    "label": "This phone",
    "created_at": "2026-10-13 16:20:00",
    "last_seen_at": "2026-10-13 17:00:00",
    "token_hint": "ExponentPushTo..."
  }
]
```

The full push token is **never** returned — it is a capability, and echoing it
back would leak it into logs and screenshots.

### `POST /api/devices`

Register a push token. Idempotent — the same token upserts.

```bash
curl -s -X POST localhost:8787/api/devices \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"expo_push_token": "ExponentPushToken[xxx]", "platform": "ios", "label": "My phone"}'
```

```json
{"id": 1, "platform": "ios", "label": "My phone"}
```

### `DELETE /api/devices/{id}`

Returns `204`. The device stops receiving alerts immediately.

Dead tokens are also pruned automatically when Expo reports
`DeviceNotRegistered`.

## Activity

### `GET /api/alerts?limit=50`

Everything that has been alerted, whether or not delivery succeeded.

```json
[
  {
    "id": 12,
    "watch_id": 1,
    "watch_label": "Coffee near work",
    "item_id": "1001",
    "title": "Magic Bag is back at Blank Street Coffee",
    "body": "3 left · 3.99 · collect by 19:00",
    "devices_ok": 1,
    "devices_err": 0,
    "created_at": "2026-10-13 17:04:09"
  }
]
```

`limit` is 1–500, default 50.

### `GET /api/runs?limit=20`

One entry per poll pass. This is the health history.

```json
[
  {
    "id": 42,
    "started_at": "2026-10-13 17:04:09",
    "finished_at": "2026-10-13 17:04:10",
    "watches": 3,
    "buckets": 2,
    "items_seen": 62,
    "matched": 5,
    "alerts": 1,
    "errors": 0,
    "blocked": 0,
    "note": null
  }
]
```

`blocked: 1` on recent runs means Too Good To Go is refusing the server. `limit`
is 1–200, default 20.

## Live search

### `POST /api/preview`

Searches Too Good To Go **live**, right now. Powers the app's Discover tab.

```bash
curl -s -X POST localhost:8787/api/preview \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"latitude": 51.5072, "longitude": -0.1276, "radius_km": 10, "query": "pret"}'
```

```json
{
  "count": 2,
  "items": [
    {
      "item_id": "1001",
      "store_name": "Pret A Manger",
      "display_name": "Magic Bag",
      "quantity": 3,
      "price": "3.99",
      "currency": "GBP",
      "distance_m": 450,
      "pickup_end": "2026-10-13T19:00:00Z",
      "category": "MEALS"
    }
  ]
}
```

| Field | Notes |
|---|---|
| `query` | Optional. Case-insensitive substring across store *and* bag name. |
| `limit` | 1–200, default 40. Applied after sorting by distance. |

**This spends a real API call against your account.** Do not poll it on a timer.
It is a user-initiated action.

Returns `409` if not logged in, `429` if Too Good To Go is blocking, with a
retry estimate in the message.

### `POST /api/preview-watch`

What a *stored* watch would match right now, without alerting.

```bash
curl -s -X POST localhost:8787/api/preview-watch \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"watch_id": 1}'
```

```json
{
  "matched": 1,
  "of_total": 62,
  "items": [{"item_id": "1001", "store_name": "Blank Street", "display_name": "Magic Bag", "quantity": 3, "price": "3.99"}]
}
```

The most useful debugging endpoint in the API. `matched: 0` with `of_total: 62`
means your patterns are wrong, not that the server is broken.

## Testing delivery

### `POST /api/test-notify`

Sends a real push. Same as `tgtg-alert test-notify`.

```bash
curl -s -X POST localhost:8787/api/test-notify \
  -H "Authorization: Bearer $TOKEN"
```

```json
{"sent": 1, "errors": 0, "messages": []}
```

Returns `409` if no devices are paired.

## Recipes

### Am I being blocked?

```bash
curl -s -H "Authorization: Bearer $TOKEN" localhost:8787/api/runs?limit=20 \
  | jq '[.[] | select(.blocked == 1)] | length'
```

Non-zero means the poller has been refused recently.

### Alert me when a watch matches nothing

```bash
for id in $(curl -s -H "Authorization: Bearer $TOKEN" localhost:8787/api/watches | jq -r '.[].id'); do
  matched=$(curl -s -X POST localhost:8787/api/preview-watch \
    -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
    -d "{\"watch_id\": $id}" | jq '.matched')
  [ "$matched" = "0" ] && echo "watch $id matches nothing"
done
```

### Pause everything

```bash
curl -s -H "Authorization: Bearer $TOKEN" localhost:8787/api/watches \
  | jq -r '.[].id' \
  | xargs -I{} curl -s -X PATCH localhost:8787/api/watches/{} \
      -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
      -d '{"enabled": false}'
```

### Home Assistant

```yaml
rest_command:
  tgtg_pause:
    url: "http://tgtg-pi:8787/api/watches/1"
    method: PATCH
    headers:
      Authorization: !secret tgtg_token
      Content-Type: application/json
    payload: '{"enabled": false}'

sensor:
  - platform: rest
    name: TGTG Alert Status
    resource: http://tgtg-pi:8787/api/status
    headers:
      Authorization: !secret tgtg_token
    value_template: "{{ value_json.last_run.alerts }}"
    json_attributes_path: "$.last_run"
    json_attributes:
      - items_seen
      - matched
      - blocked
```

For alerts *into* Home Assistant, set `TGTG_WEBHOOK_URL` — see
[Configuration](configuration.md#tgtg_webhook_url).

## Interactive docs

FastAPI generates its own reference at `/docs` (Swagger UI) and `/redoc`,
covering the same surface with a live "try it" console. Both are unauthenticated,
so they are useful for exploring but **expose your endpoint list** — mind that if
the server is publicly reachable.
